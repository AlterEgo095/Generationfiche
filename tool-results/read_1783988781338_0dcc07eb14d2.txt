    43→## API CONTRACT (à respecter par backend + frontend)
    44→
    45→### Routes REST (Next.js API, App Router, src/app/api/...)
    46→- GET  /api/dashboard                    → { counts: {sequences, livrables, corpus, notions, agentRuns}, byStatut: {validee,en_cours,planifiee,en_attente,echec}, funnel: {generees, structurel_ok, pedagogique_ok, validees}, recentRuns: AgentRun[], recentLivrables: Livrable[] }
    47→- GET  /api/sequences?statut=&niveau=&chapitre=  → Sequence[]
    48→- GET  /api/sequences/[id]               → Sequence + notions + generationContext + livrables(validations) + agentRuns
    49→- POST /api/sequences                    → create manually (body: {titre, niveau, chapitre, semaine, notionIds[], priorite, contexteClasse?})
    50→- GET  /api/corpus?type=&niveau=&chapitre=&statut=&exemplaire=  → CorpusVectoriel[]
    51→- POST /api/corpus                       → create (body: {contenu, type, niveau, chapitre, notionId?, exemplaire?})
    52→- PATCH /api/corpus/[id]                 → update (body: {statut?, exemplaire?, contenu?})
    53→- GET  /api/agent-runs?agent=&batchId=&sequenceId=  → AgentRun[]
    54→- GET  /api/skills                       → SkillDescriptor[]
    55→- GET  /api/templates                    → FicheTemplate[]
    56→- GET  /api/referentiel                  → { notions, prerequis, progressions, regles }
    57→- GET  /api/livrables/[id]               → Livrable + validations
    58→- POST /api/pipeline/generate            → { mode: 'single'|'batch', sequenceId?, demande?, skillVersion: 'v1'|'v2', validateVersion: 'v1'|'v2' } → { batch_id, items: BatchPlanItem[], started_at }
    59→- GET  /api/pipeline/batch/[id]          → { batch_id, items: [{sequence_id, statut, livrable_id?}], stats }

    61→### WebSocket mini-service (port 3003)
    62→- Frontend connect: io("/?XTransformPort=3003")
    63→- Client emits: { event: 'subscribe', data: { batch_id } }

    65→- PipelineEvent: { batch_id, sequence_id?, agent, skill?, phase: 'start'|'progress'|'done'|'error'|'retry'|'escalade', message, payload?, timestamp, duration_ms? }

   139→Deviations from spec (with rationale):
   140→1. **Donut chart custom SVG inline** instead of recharts — lighter, no extra deps, exact styling control. Same visual outcome (segments + center count).
   141→2. **Funnel custom horizontal bars** instead of Recharts BarChart — simpler animation via framer-motion, exact label/percentage alignment.
   142→3. **Layout split into `layout.tsx` (server) + `providers.tsx` (client)** — required because QueryClient is a class instance and can't be serialized from a Server Component. Standard React Query + Next.js App Router pattern.
   143→4. **`useSyncExternalStore` for mounted state in TopBar** instead of `useEffect(() => setMounted(true))` — React 19 ESLint rule `react-hooks/set-state-in-effect` blocks the standard pattern. `useSyncExternalStore` is the canonical alternative.
   144→5. **`usePipelineEvents` uses derived-state-on-prop-change pattern** (`prevBatchId` ref) to reset events when batchId changes — avoids setState-in-effect lint violation while preserving behavior.
